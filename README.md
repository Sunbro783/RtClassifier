# 🩺 RtClassifier — классификация систем реального времени и расчёт требуемого времени реакции

> Консольное приложение на C# для анализа набора задач системы реального времени на примере **медицинского монитора**.

---

## 📌 Описание проекта

Проект выполнен в рамках **практической работы № 1** по дисциплине «Вычислительные системы реального времени» по теме «Классификация систем реального времени и расчёт требуемого времени реакции».

Прикладная система — **медицинский монитор**. Анализируются задачи:

- контроль сердечного ритма;
- тревога по порогу;
- обновление экрана;
- запись в архив.

Для каждой задачи задаются имя, класс жёсткости (жёсткое / твёрдое / мягкое), время выполнения `C`, относительный дедлайн `D` и период `T` в миллисекундах. Система в целом задаётся числом процессоров и признаком наличия сети.

---

## 🚀 Возможности

- Классификация каждой задачи по жёсткости и определение класса системы (жёсткого или мягкого реального времени)
- Определение типа дедлайна по соотношению `D` и `T` (неявный, ограниченный, произвольный)
- Расчёт запаса времени `L = D − C` и признака выполнимости дедлайна (`L ≥ 0`)
- Поиск критической задачи — жёсткой задачи с наименьшим запасом
- Расчёт требуемого времени реакции системы `R_треб = min D` (по жёстким задачам, а при их отсутствии — по всем)
- Расчёт коэффициента загрузки `U = Σ(C / T)` и проверка необходимого условия `U ≤ N` (для одного процессора `U ≤ 1`)
- Определение архитектуры: однопроцессорная, многопроцессорная или распределённая
- Чтение исходных данных из JSON-файла, без «зашитых» в код значений
- Проверка входных данных с понятными сообщениями об ошибках
- Вывод таблицы результатов и итогового заключения в консоль

### Расчётные функции (`TaskAnalysis.cs`)

| Функция | Назначение |
| --- | --- |
| `Slack(task)` | Запас `L = D − C` |
| `IsFeasible(task)` | Признак `L ≥ 0` |
| `GetDeadlineType(task)` | Тип дедлайна |
| `ClassifySystem(tasks)` | Класс системы |
| `CriticalTask(tasks)` | Критическая задача |
| `RequiredReactionTime(tasks)` | Требуемое время реакции |
| `Utilization(tasks)` | Коэффициент загрузки |
| `ClassifyArchitecture(cpuCount, hasNetwork)` | Архитектурный класс |

Задача описана записью `RealtimeTask` (аналог `@dataclass`): имя, класс жёсткости, `C`, `D`, `T`.

| Задача | Класс | C, мс | D, мс | T, мс |

## 📐 Расчёты

```
L = D − C                запас времени
L ≥ 0                    дедлайн выполним по собственному времени
R_треб = min D           требуемое время реакции
U = Σ (C / T)            коэффициент загрузки
U ≤ N                    необходимое условие (N — число процессоров)
```

Тип дедлайна определяется по соотношению `D` и `T`:

- `D = T` — неявный
- `D < T` — ограниченный
- `D > T` — произвольный

Условие `U ≤ N` необходимое, но не достаточное: оно не заменяет анализ расписания.

## ▶️ Запуск

### Visual Studio 2022

1. Откройте `RtClassifier.sln`.
2. Нажмите **F5** или **Ctrl+F5**.

Файл данных копируется в папку сборки автоматически, дополнительных настроек не нужно.

### Командная строка

Требуется [.NET 8 SDK](https://dotnet.microsoft.com/download).

```
git clone https://github.com/Sunbro783/RtClassifier.git
cd RtClassifier
dotnet run --project src/RtClassifier
```

Свой файл данных можно передать аргументом:

```
dotnet run --project src/RtClassifier -- data/variant_medical_monitor.json
```

## ⚠️ Обработка ошибок

При некорректных данных программа выводит сообщение вида `Ошибка: …` и завершается с кодом 1. Проверяются: существование файла, наличие названия системы и задач, число процессоров (не меньше 1), известный класс жёсткости, положительные значения `C`, `D` и `T`.
